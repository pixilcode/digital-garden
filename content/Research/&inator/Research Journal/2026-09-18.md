## Compilation problems

```
usr/include/gnu/stubs.h:7:11: fatal error: 'gnu/stubs-32.h' file not found
  7 | # include <gnu/stubs-32.h>
    |           ^~~~~~~~~~~~~~~~ 
```

This can be resolved by installing `glibc-devel.i686` with the following command:

```sh
dnf install glibc-devel.i686
```

However, this then produces the following error:

```
/usr/include/bits/floatn.h:97:9: error: __float128 is not supported on this target
   97 | typedef __float128 _Float128;
      |         ^

Based on an analysis by AI, it seems like the problem is that `clang` is using the wrong libraries for compilation (`x86_64` as opposed to `aarch64`), which is causing invalid requirements.

AI recommends that I change the top line of the Dockerfile to

```
FROM --platform=linux/arm64 fedora:42

## Function pointers
### What does a function pointer look like?

A function pointer has the syntax `<ret_type> (* fn_name)(param_types...)`.

### How does a function pointer translate to LLVM?

I was able to successfully get this working with the following C code.

```c
int add(int *x, int *y) {
    return *x + *y;
}

int calc(int (*f)(int*, int*), int x, int y) {
    return (*f)(&x, &y);
}

int main() {
    int result = calc(&add, 1, 2);
    return 0;
}
```

This causes &inator to fail stating that it doesn't support function pointers. **I need to figure out where this happens.**

## Constants

### What does this look like in C code?

Victor gave me this code, but it doesn't quite compile.

```c
#include <stdlib.h>
int main() {
    int a;
    *NULL = &a;
    return 0;
}
```

The goal is to produce LLVM code like this:

```llvm
define i32 @main() {
entry:
    %a = alloca i32
    store ptr %a, ptr null
    return i32 0
}
```

The closest replication I could find is

```c
#include <stdlib.h>

int main() {
    int* a = NULL;
    int b;
    *a = b;
    return *a;
}
```

However, this just compiles to

```llvm
define dso_local i32 @main() #0 {
entry:
  unreachable
}
```

so it isn't a useful reproduction. **I need to figure out a different way to get constants to appear in the code.**
